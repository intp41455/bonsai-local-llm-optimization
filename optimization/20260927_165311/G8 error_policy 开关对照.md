# G8 `tools.error_policy` 开关对照（同一份 v3 脚本，仅切常驻策略块）

生成时间：2026-09-28 04:58　执行方：TRAE Agent

主批窗口：2026-09-28 04:30:39 → 04:54:06（约 23.5 分钟）　补批窗口：04:56 → 04:58

## 一、为什么做这一批

G7（`G7 代理转发内容对照.md` §6）实测确认：v3 相对 v2 转发内容的**唯一实质差异**，是
`tools.error_policy=true` 触发 `apply_tool_error_policy()` 在首条 system 文本尾部追加的 **584 字符常驻策略块**
（`TOOL_POLICY_BLOCK`）。G7 同时明确：**该结论只证明「转发内容差在哪」，不构成任何能力/好坏判定**，
其收益场景（工具错误连续重试）与对通用任务的影响方向**均未测**，并建议「另立『同代码开关 `tools.error_policy`』对照，
不要在 G5/G6 数据上推断」。

本批即是该对照：**同一份 v3 脚本（sha256 `6ACFB9C5…`）**，两臂各起独立代理，**仅** `tools.error_policy`
取值不同（P=true / Q=false），其余配置逐字段一致，跑同一套固定任务，判定该策略块对通用任务的影响方向。

## 六、口径与局限（必须遵守）

1. **样本与确定性**：`temperature=0.0`，每任务每臂 2 轮；两臂各自两轮**逐字节完全相同**，
   说明本批在**确定性解码**下可复现。但 **n=2、任务仅 4 项**，**不得**把任务 8 的方向性差异
   外推为「策略块在所有通用任务上都有害」。
2. **影响是任务相关的**：本批**只有任务 8** 出现方向性差异；任务 3、6 两臂均满分。
   策略块对**任务 8（单文件图形生成）**为负向，对**任务 3/6** 无能力影响（仅过程指标差异）。
3. **不测收益场景**：`TOOL_POLICY_BLOCK` 的目标场景是**工具错误连续重试**；本批固定任务里
   该场景**未被触发**，故本批**不评估其收益**，也**不能**据此判定「应删除该功能」。
4. **token 口径**：主批 token 取**各臂自身** `logs/requests.jsonl` 增量（字段 `prompt_evaluated_tokens` /
   `cache_reused_tokens` / `prefill_ms` / `decode_tps` / `finish_reason`，`token_source` 已记录）。
   harness 内部 `proxy_records` 恒为 0——因 `bench_harness.py` 的 `PROXY_LOG` **硬编码生产路径**，
   只作留痕、**不作本批数据来源**；本批**未**依赖生产日志取数。
5. **未做的事**：说明：本批**未**做 P/Q 的 token 量对照（两臂输入必然差 584 字符，
   但该差异量与「输出是否合法」不是同一命题），也**未**做多温度/多种子重复。
6. **任务 11 主批无效**（§3.4），其结论仅来自 §七 补批。

## 十、结论与建议

1. **开关级因果确认**：同一份 v3 脚本、仅切 `tools.error_policy`，任务 8 结果**完全翻转**——
   P（true，含 584 字符常驻策略块）**0/2 失败**（47 行 / 2468 B / XML 非法），
   Q（false）**2/2 通过**（58 行 / 3017 B / XML 合法）；且 G8-P ≡ G6-B、G8-Q ≡ G6-A **逐字节相同**。
   → v3 在任务 8 上的失败，**由 `tools.error_policy` 单独决定**，与 v3 其余改动无关。
2. **影响是任务相关的，不是全局的**：任务 3、6（含补批后的任务 11）两臂**均满分、无能力差异**；
   唯一差异出现在任务 8（单文件图形生成）。故**不能**推广为「策略块在所有任务上有害」。
3. **收益未测**：策略块面向「工具错误连续重试」，本批任务集**未触发**该场景，**不得**据此判定
   「应删除 `error_policy`」。若要评估收益，需另设**触发工具错误**的对照任务集。
4. **过程指标的异常留痕（不作结论）**：P 臂任务 3 轮数 15 / 工具重复 8，Q 臂为 9 / 0；
   方向与策略块第 1 条设计意图相反，但 n=2、仅 1 项任务，仅作留痕。
5. **生产候选建议**：若后续要落地「关闭 `error_policy`」，须先补两步——① 设计并跑**工具错误重试**场景对照，
   确认收益是否真的存在；② 在**多任务 × 多次**样本上确认任务 8 的负向是否可复现且不引入其它回归。
   本批**不构成**改生产配置的依据。
6. **待办**：① 任务 10（压缩边界五轮）仍缺驱动；② A 臂（v2）CAP 硬编码会向生产抓包目录落
   `small_*.json` 的副作用（G7 已记）仍未处理。
