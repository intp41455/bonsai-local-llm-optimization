## 三、选择任务档

档位全部写在 `config\bonsai-agent.json`，**改配置后需让新配置生效**（见本节末）。

### 3.1 思考档 `thinking.default_effort`

取值 `xhigh` / `medium` / `low` / `off`，当前默认 **`medium`**。

| 值 | 含义 |
|---|---|
| `medium` | **不注入任何思考指令** = 模型自然行为，推荐 Agent 场景（当前值） |
| `xhigh` / `low` | 注入对应模板思考档（档位拼在 system 前缀里） |
| `off` | 关闭思考 |

注意：**一轮会话固定一档，中途切换会让 KV 前缀作废**（等于重新预填充）。

### 3.2 预算档 `budget`

| 键 | 当前值 |
|---|---|
| `request_max_tokens` | 8192（总生成 = 思考 + 答案） |
| `thinking_budget_tokens` | 2048 |
| `context_reserve_tokens` | 1024 |
| `context_window_tokens` | 65536 |
| `policy.apply_request_max_tokens` | **false** |
| `policy.apply_thinking_budget` | **false** |

`policy.*=false` 表示**只登记、不注入**请求级预算（阶段 D 已行为验证该二进制支持请求级 `reasoning_budget_tokens`；
是否改为注入属需用户决定的候选，见四类状态清单）。

### 3.3 瘦身档 `slimming`（三项各自独立）

| 键 | 当前值 | 效果 |
|---|---|---|
| `locations` | **true** | 剥掉 `(location: C:/.../SKILL.md)` 纯磁盘路径（省约 4,931 tok，零功能代价） |
| `deferred_tools` | **false** | 不压缩 ToolSearch 的 deferred 工具名册（保留发现能力） |
| `subagents` | **false** | 不压缩子代理类型名册（保留发现能力） |

### 3.4 其他固定项

- **MTP：关**（`backend.mtp.enabled=false`）。历史证据显示长上下文开 MTP 为负收益；仅短输入+显存余量+正确性满足时才在 G4 重测。
- 采样：`server_default`（不传采样参数，用服务端默认 temp 1.0 / top-k 20 / top-p 0.95 / min-p 0.05）。
- 上下文 `-c 65536` / `-np 1`（单槽，请求会被代理串行化）。

### 3.5 改档位后如何生效（重要）

`launcher up` 的"在线参数 vs 配置"差异检测**只比对命令行参数**：

- 改 **`thinking.default_effort`** → `--effort` 是命令行参数 → `launcher up` 会**自动重启代理**。
- 改 **`slimming.*` / `budget.*` / `tools.*`**（都在配置文件内容里）→ launcher 检测不到差异 →
  **必须手动重启代理**，否则在线跑的仍是旧配置：

```bat
"%PY%" -u D:\Bonsai-demo\launcher\bonsai_launcher.py status      # 记下 [代理] PID
:: 核对该 PID 命令行确为本项目 proxy\bonsai_proxy.py 后停掉它
"%PY%" -u D:\Bonsai-demo\launcher\bonsai_launcher.py up --no-prewarm   # 只拉起代理
```

后端 `llama-server` 不受影响（无需重启，模型不重载）。

## 四、处理超预算

输入预算闸门 `budget.gate`（当前 `enabled=true`，**`mode=warn`**）：

| 模式 | 行为 |
|---|---|
| `warn`（当前） | 判定超预算时**只告警并转发**，请求照常执行 |
| `reject` | 在**生成前返回 400**（`error.type=input_over_budget`），**不占槽位、不消耗 GPU** |

判定口径：`输入 token + 计划生成 + 上下文余量 <= 有效上下文窗口`。token 数由后端
`/apply-template` + `/tokenize` 精确核算（与真实请求共用同一模板路径）；只有字符上界估算已能安全放行时才跳过精确计数。
**绝不静默裁剪历史**；计数失败记 `unknown`，不当作"安全放行"。

切换模式（只改一处文本 + JSON 校验）：

```bat
"%PY%" D:\Bonsai-demo\optimization\20260927_165311\tests\set_gate_mode.py reject
:: 然后按 3.5 手动重启代理
```

客户端收到 400 时：**减少输入**（整理历史 / 拆分任务）或**降低计划生成预算**后重试。

查是否命中：`logs\requests.jsonl` 的预算检查字段 / `logs\proxy.log` 的 `[预算]` 行。

## 五、取消任务

- 客户端取消/断开时，代理用非阻塞 `MSG_PEEK` 检出（不依赖"写失败"，因为单槽下后端仍会写满缓冲）；
- 检出后**关闭上游连接**，并在窗口 `timeouts.release_wait_s=30s` 内**轮询 `/slots` 验证后端确实释放了槽位**
  （方案 §C2：**不假设 `close` 就等于取消**）；
- 记录 `client_disconnected=true` 并写入 `requests.jsonl`；流结束时才发现客户端已断开也会补记。
- 超时（connect / first_response / stream_idle / overall）同样走上游关闭 + 释放验证。

若日志显示"取消/超时后 /slots 释放验证：失败"，说明后端可能仍占用单槽，届时用 `launcher status` 看 `is_processing`，
必要时按 `rollback.md` 铁律停掉**核对过身份**的代理/后端 PID。

## 六、回滚入口

完整回滚方案见 `optimization\20260927_165311\rollback.md`（R0~R7，含每个阶段的备份路径与 SHA256）。
铁律：**不按端口盲杀、不 `git reset --hard`、不覆盖其他 agent 在备份后新增的改动**；停止只操作 state 里核对过身份的 PID。

最快的代理回滚（已由阶段 H2 演练实测通过，见 `rollback.md` R7）：

```bat

:: 2) 覆盖为阶段 F 之前版本

:: 3) 拉起

:: 4) 复验

"%PY%" -u D:\Bonsai-demo\launcher\bonsai_launcher.py smoke
```

build=`b181-9ef3205`、`n_ctx=65536`、smoke 0.94s `finish=stop`；前滚复原后 sha256 回到 `6ACFB9C5...`、smoke 0.55s。

## 七、不要做的事

- 不要直连 `:8081`（绕过瘦身/预算/契约加固，且 8080 才是客户端入口）。
- 不要加 `--kv-mean-center`（属旧 kvmem 路线，与 MTP 互斥，会让接受率崩到 0）。
- 不要按端口 `taskkill` / 盲杀健康服务。
- 不要同时起两个模型进程（`-np 1` 单槽；显存 8GB 已被模型吃满）。
- 不要手动改各 `start_*.bat` 里的参数：它们现在只是入口包装，唯一配置源是 `config\bonsai-agent.json`。
