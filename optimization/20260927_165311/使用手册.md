# Bonsai 本地模型服务 使用手册

> 版本：2026-09-28（G14 生产切 reject + floor 1.5；G15 400 观测埋点已上线）
> 唯一配置源：`D:\Bonsai-demo\config\bonsai-agent.json`

## 1. 能否直接使用

是。当前为可用状态，且已在生产生效的最新保护：

- 代理 `:8080` 正常运行（`/health` → 200）
- 后端 `:8081` 正常运行（`/health` → 200）
- 预算闸门 `mode=reject` + `chars_per_token_floor=1.5`（G14）
- 400 观测埋点已上线（G15）

## 2. 最推荐的使用入口

**连代理 `:8080`，不要直连后端 `:8081`。**
代理层负责瘦身、思考档位、预算闸门（reject）、400 观测埋点；直连后端会绕过这些保护。

```
OpenAI 兼容 base_url : http://127.0.0.1:8080/v1
model                : bonsai-2-27b
鉴权                 : 无（本机服务，直接可用）
```

所有 OpenAI 系客户端（SDK / WorkBuddy / Pi / curl）只需把上述地址填入即可。

## 3. 快速验证（curl / PowerShell）

```powershell
# 健康检查
Invoke-RestMethod http://127.0.0.1:8080/health

# 一问一答
$body = @{
    model     = "bonsai-2-27b"
    messages  = @(@{ role = "user"; content = "用一句话介绍你自己" })
    max_tokens = 256
    stream    = $false
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/v1/chat/completions `
                  -ContentType "application/json" -Body $body
```

同样的 `POST /v1/chat/completions` 抛给 WorkBuddy / Pi 的模型配置即可接入。

## 4. 请求参数要点

| 参数 | 说明 |
|---|---|
| `model` | `bonsai-2-27b` |
| `stream` | 建议 `true`（默认支持流式） |
| `temperature` | 需要确定性时设 `0.0` |
| `max_tokens` | 请求级预算上限，配置默认 8192；提交值勿低配太多，否则长回复被截断 |

## 5. 长文本 / 预算（重要）

- 闸门阈值 = 56,320 token（= 65536 − 8192 − 1024）。
- 生效为 **reject 模式**：输入 **超过阈值 → 直接返回 400**（`input_over_budget`），不再硬跑，也不占用推理槽。
- **多轮 / 粘贴长文前请精简或拆分**，否则会收到 400。
- 触发 400 后可在 `logs\proxy.log` 看到 `[400观测]` 行，在 `logs\requests.jsonl` 看到带 `client_mark` 的记录。

## 6. 并发与性能

- 后端 `-np 1`，**单槽串行**：同一时刻只处理一个推理请求，其余排队。
- 后端 `--cache-ram 1024`：短会话快速、省主机内存；跨会话长上下文复用有限（观测中）。

## 8. 400 行为观测（G15 + 每日汇总）

- 每次 reject 都会在 `requests.jsonl` 记 `client_mark`（客户端指纹：UA / Authorization 前缀 / X-Stainless-* / X-* 等）。
- 每次 reject 后在 `proxy.log` 打 `[400观测]` 行，含 `conn=closed|alive`（打开连接后是否断开）。
- 已建**每日 09:00 定时任务**：自动跑 `.stage\g15_aggregate.py` 汇总 400 事件、连接状态、重试信号（每条 400 后 60s 内是否再次请求、几次、是否成功）。
- 聚合脚本：
  `python .stage\g15_aggregate.py`（整观测期）／`--days 1`（近 1 天）／`--since YYYY-MM-DD`。

## 10. 局限与建议

- 单槽串行，不适合高并发；长上下文跨会话复用有限。
- `reject` 只拦截「闸门正确判出超预算」的路；真实客户端收到 400 后是报错还是自愈重试，正在观测中（G15/G16），拿到数据后再决定是否加客户端侧智能降级。
