### 1.5 由证据得到的结论

**已证实（有直接产物/计数器支持）**

1. **页面文件不是瓶颈**：已分配 73,728 MB，实际占用仅 746 MB、峰值 592/564 MB。→ 调大 pagefile 无收益。
2. **mmap 的模型文件页基本未驻留**：`Working Set − Private`（5,801 MB）≈ 总 Working Set（5,816 MB），
   即工作集 **99.7 % 为私有页**，文件页几乎为 0；权重已在显存（GPU 7,122/8,151 MiB）。
3. **后端持有约 16.6 GiB 私有提交，但仅 4.2–5.8 GiB 驻留**，同时累计页错误 **3,175 万次**
   （81 min → 均值 ≈ 6,500 次/秒）、`pages input/sec ≈ 1.02 万`。
   → 宿主管存压力表现为**压缩/换页往返（硬缺页抖动）**，而非"容量不足"。
4. **服务端宿主 prompt cache 处于激活状态**（1.3 的 `kv_unified='false'` + 12 条 GiB 级淘汰记录）
   且其**默认上限为 8192 MiB**（1.2）。

**推断（强线索，但本轮未逐项拆解，不得当作已确认）**

- `--cache-ram` 8192 MiB 的宿主 prompt cache 是上述 16.6 GiB 私有提交的**主要构成之一**。
- 见 §1.6：本轮尝试按 `MEM_PRIVATE / MEM_MAPPED` 分解地址空间失败，因此"16.6 GiB 的构成拆解"
  仍属**未验证**。以上仅由"默认值 + 激活状态 + GiB 级淘汰记录"三条线索支撑。

**已排除**

- 页面文件容量调整（证据 1）。
- mmap 模型文件页残留占用（证据 2）。
